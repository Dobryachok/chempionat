# Воздушный шар — бонусная crash-игра с турнирной механикой

Рабочий веб-прототип бонусной игры для «Столото»: игрок ставит бонусные баллы и старается забрать
растущий выигрыш до того, как шар лопнет. Вся случайность и все расчёты выполняются на сервере,
клиент только отображает то, что присылает бэкенд.

- Frontend: React 19 + TypeScript + Vite, анимации на CSS и `requestAnimationFrame`, звуки синтезируются через Web Audio.
- Backend: Java 21 + Spring Boot 3 (REST + WebSocket), H2 + Spring Data JPA, внешний конфигурационный файл с горячей перезагрузкой.
- Реальное время: WebSocket-канал раунда (тики коэффициента, уровни, бустер, cashout, crash) и polling турнира раз в секунду.

## Быстрый старт

Требуется JDK 21+ и Node.js 20+. В этом окружении переносимые JDK 21 и Maven лежат в папке `tools/`
(она не входит в репозиторий), поэтому команды ниже используют именно их.

### 1. Бэкенд (порт 8080)

PowerShell:

```powershell
$env:JAVA_HOME = "D:\chempionat\tools\jdk-21.0.5+11"
$env:Path = "$env:JAVA_HOME\bin;D:\chempionat\tools\apache-maven-3.9.9\bin;$env:Path"
cd D:\chempionat\backend
mvn spring-boot:run
```

Если в системе уже установлены JDK 21+ и Maven, достаточно `mvn spring-boot:run` в папке `backend`.

### 2. Фронтенд (порт 5173)

```powershell
cd D:\chempionat\frontend
npm install
npm run dev
```

Откройте <http://localhost:5173>. Vite проксирует `/api` и `/ws` на бэкенд, поэтому дополнительная
настройка не нужна.

Прод-сборка: `npm run build` и `npm run preview` (порт 4173, тот же проксирующий конфиг).

### 3. Демонстрационный доступ

Регистрация не нужна: при первом запросе создаётся демонстрационный игрок **«Вы»** с балансом
**12 450 бонусных баллов** и 7 820 игровыми очками, а также 10 соперников для живого рейтинга и
турнирной таблицы. Баланс восстанавливается заново, если удалить папку `backend/data`.

## Проверка обязательных сценариев

| Сценарий | Где проверять |
| --- | --- |
| 1. Выбор ставки и запуск игры | Главный экран → «Зелёный шар» или «Красный шар» → экран ставки: 4 фрагмента, бустеры, история игр, правила, 9 или 12 уровней |
| 2. Успешный cashout | В полёте нажать «Забрать» после первого уровня → плашка «Могли бы забрать больше» → после краха экран результата и запись в истории |
| 3. Проигрыш | Не нажимать «Забрать» → «Шар сдулся!», коэффициент краха, начисленные очки, награда |
| 4. Активация бустера | Выбрать фрагмент с бустером x2–x4: маркер виден на лестнице уровней, при достижении коэффициент умножается со вспышкой |
| 5. Управление параметрами | `/admin` в интерфейсе либо файл `backend/config/game-config.json` (перечитывается автоматически) |

Дополнительные сценарии 6–8: живой рейтинг в верхней строке игрового экрана, турнирная таблица по
кнопке с кубком, окно «Закрепи успех» после выигрыша от 50 баллов (не чаще одного раза за сессию).

Автоматическая проверка сквозного цикла через реальный REST и WebSocket:

```powershell
node scripts/smoke-test.mjs
```

Скрипт прогоняет сценарии 1–5, проверяет историю, турнир, деперсонализацию имён, применение
`points_per_line` через админ-API и отклонение недопустимых значений.

## Структура

```
backend/         Spring Boot: игровой движок, REST + WebSocket, H2, админ-API
  config/        game-config.json — параметры игры (правится без пересборки)
frontend/        React + TypeScript: экраны, анимации, звуки, админ-панель
docs/            архитектура, математическая модель, справочник параметров
scripts/         smoke-test.mjs — сквозная проверка обязательных сценариев
```

## Реализованные функции

Обязательный минимум:

- экран выбора ставки с 4 фрагментами пазла (стоимость + бустер), блокировкой при недостатке баллов и уведомлением «Не хватает бонусов»;
- crash-механика: серверный рост коэффициента, уровни (9 зелёных, 12 красных), «Забрать» после первого уровня, продолжение полёта после cashout, потеря ставки при крахе;
- бустеры x2–x4 со случайной позицией уровня, вспышкой и дополнительными очками;
- экраны результата с выигрышем, коэффициентом, очками, наградой-фрагментом коллекции и кнопками «Играть снова» и «Повторить с той же ставкой», автопереход через 10 секунд бездействия;
- общая история завершённых раундов всех игроков прототипа;
- правила игры, соответствующие реализованной механике;
- управление всеми параметрами через админ-панель и через конфигурационный файл с горячей перезагрузкой и валидацией.

Дополнительно:

- отдельный экран выбора темы с анимированным небом (1–3 птицы и 1–3 облака со случайными траекториями) и парящими шарами;
- живой рейтинг турнира на игровом экране с короткой и длинной вспышками при изменении очков;
- турнирная таблица: закреплённый топ-3, прокрутка, закреплённая строка игрока, таймер, деперсонализация имён;
- окно «Закрепи успех» с персонализированным предложением билетов, автозакрытием и однократным показом за сессию;
- мини-онбординг подсказки «Забрать», смена стиля коэффициента по уровням, эффекты «+X»;
- звуки без бинарных ассетов: птицы каждые 1.8–5 с, капля воды при выборе темы, уровни, бустер, крах, монеты;
- упрощённая схема provably fair: хеш до полёта, раскрытие секрета после краха;
- восстановление незавершённого раунда после перезагрузки страницы (в течение часа), профиль с коллекцией фрагментов.

## Известные ограничения

- Авторизации нет: прототип работает с одним демонстрационным игроком, соперники имитируются серверным симулятором.
- Покупка лотерейных билетов и начисление баллов имитируются, внешние платёжные и лотерейные системы не подключены.
- Проверка честности реализована как отображение хеша и раскрытие секрета; автоматической верификации на клиенте нет.
- H2 хранится в файле `backend/data`, миграции не используются — схема создаётся Hibernate.
- Изменения параметров применяются к следующему раунду: уже летящий шар продолжает играть по снимку конфигурации, сделанному на старте.
