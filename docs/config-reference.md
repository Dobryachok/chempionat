# Справочник параметров игры

Все параметры игры вынесены во внешний файл `backend/config/game-config.json`. Он не входит в jar и
правится без пересборки. Путь задаётся свойством `game.config-path` в
[`application.yml`](../backend/src/main/resources/application.yml).

## Порядок применения изменений

Есть два равноправных способа:

1. **Админ-панель** — страница `/admin` в интерфейсе. Значения проверяются, записываются в файл и
   применяются сразу; в ответе видна новая версия конфигурации.
2. **Правка файла вручную** — `backend/config/game-config.json`. Файл наблюдается через `WatchService`
   и перечитывается автоматически через несколько десятых секунды после сохранения. Перезапуск сервера
   не требуется.

В обоих случаях новые значения действуют начиная со **следующего раунда**: уже летящий шар доигрывает
по снимку конфигурации, сделанному на старте. Если значения не проходят валидацию, изменения
отклоняются: админ-API возвращает HTTP 422 со списком ошибок, а при ручной правке в логе появляется
предупреждение и продолжает работать последняя корректная конфигурация.

Проверить состояние можно запросом `GET /api/admin/status` — он возвращает путь к файлу, версию и
время последнего применения.

## Базовые параметры

| Параметр | Тип | Допустимо | Назначение |
| --- | --- | --- | --- |
| `basic.gameId` | строка | не пусто | Идентификатор игры |
| `basic.gameName` | строка | не пусто | Отображаемое название |
| `basic.gameType` | строка | не пусто | Тип игры (`crash`) |
| `basic.isActive` | булево | `true` / `false` | При `false` новые раунды не стартуют |

## Математическая модель

| Параметр | Диапазон | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `math.alpha` | 0.2 … 10.0 | 1.15 | Форма распределения Парето: меньше — дольше полёты и выше отдача |
| `math.minCrashMultiplier` | 1.0 … 10.0 | 1.0 | Минимальная точка краха |
| `math.maxMultiplier` | 1.5 … 1000.0 | 50.0 | Максимальный коэффициент, обрезает хвост распределения |
| `math.multiplierGrowthRate` | 0.0005 … 0.5 | 0.012 | Прирост коэффициента за один тик |
| `math.fps` | 5 … 60 | 20 | Число тиков в секунду, которые сервер рассылает клиенту |
| `math.delta` | 0.001 … 1.0 | 0.01 | Шаг округления публикуемого коэффициента |
| `math.instantCrashProbability` | 0.0 … 0.5 | 0.03 | Доля раундов с крахом сразу на минимальном коэффициенте |

Дополнительное правило: `minCrashMultiplier` должен быть строго меньше `maxMultiplier`.

## Окно «Закрепи успех»

| Параметр | Диапазон | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `upsell.minWinAmount` | 0 … 1 000 000 | 50 | `MIN_WIN_AMOUNT`: минимальный выигрыш для показа окна |
| `upsell.popupTimeoutSeconds` | 1 … 120 | 10 | `POPUP_TIMEOUT`: автозакрытие без взаимодействия |
| `upsell.ticketPrice` | 1 … 1 000 000 | 100 | Цена одного лотерейного билета в бонусных баллах |
| `upsell.maxTickets` | 1 … 50 | 5 | Максимум билетов в предложении |

Количество билетов рассчитывается на сервере: `tickets = clamp(1 + выигрыш / (2 × ticketPrice), 1,
maxTickets)`, плюс один билет при ставке от 500, и уменьшается, если итоговая цена превышает баланс.

## Темы

Блок `themes` содержит ровно две темы: `green` и `red`.

| Параметр | Ограничения | Назначение |
| --- | --- | --- |
| `title` | не пусто | Название темы в интерфейсе |
| `levels` | 1 … 30, равно длине `levelMultipliers` | Количество уровней (9 у зелёной, 12 у красной) |
| `levelMultipliers` | строго возрастающий список, значения больше 1.0 | Пороги коэффициента для уровней |
| `lootProbabilities` | по одному неотрицательному значению на уровень, сумма больше 0 | Аналог `line_N_loot_prob`: вес уровня при выборе позиции бустера, нормируется автоматически |
| `betOptions` | ровно 4 элемента | Фрагменты пазла: `id` (не пусто), `cost` (1 … 1 000 000), `boosterTier` (1 … 4) |

В админ-панели количество уровней задаётся не отдельным полем, а длиной списка порогов: сохранение
приводит `levels` в соответствие со списком.

## Режим разработчика

| Параметр | Значение | Назначение |
| --- | --- | --- |
| `dev.fixedSeed` | строка или `null` | При заданном значении каждый раунд использует один и тот же seed: точка краха и позиция бустера воспроизводятся. Для случайной игры оставьте `null` |

## Пример проверки сценария 5

1. Открыть `/admin`, изменить `points_per_line` с 10 на 50, нажать «Сохранить и применить».
2. Начать новый раунд и дойти до первого уровня: всплывающий эффект покажет `+50`, а на экране результата
   в поле «Игровые очки» будет учтено новое значение.
3. Тот же результат даёт правка `backend/config/game-config.json` в текстовом редакторе — файл
   перечитывается автоматически, перезапуск не нужен.

Полностью автоматически это проверяется командой `node scripts/smoke-test.mjs`.
