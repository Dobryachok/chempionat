# Математическая модель

Все случайные величины раунда вычисляются на сервере в
[`CrashGenerator`](../backend/src/main/java/ru/stoloto/balloon/game/CrashGenerator.java) до начала
полёта, а рост коэффициента — в
[`RoundEngine`](../backend/src/main/java/ru/stoloto/balloon/game/RoundEngine.java).

## 1. Точка краха

Используется распределение Парето из брифа с дополнительной вероятностью мгновенного краха:

```
u ~ Uniform(0, 1)

если u < instant_crash_probability:
    crash = min_crash_multiplier
иначе:
    v     = (u - instant_crash_probability) / (1 - instant_crash_probability)
    crash = clamp(min_crash_multiplier * (1 - v) ^ (-1 / alpha), min_crash_multiplier, max_multiplier)
```

Функция выживания при `min_crash_multiplier = 1`:

```
P(crash >= x) = (1 - instant_crash_probability) * x ^ (-alpha),  x >= 1
```

Для значений по умолчанию (`alpha = 1.15`, `instant_crash_probability = 0.03`, `max_multiplier = 50`):

| Коэффициент | Вероятность дожить до него |
| --- | --- |
| 1.25 (уровень 1, зелёная) | 75.1% |
| 2.00 | 43.7% |
| 3.30 (уровень 6, зелёная) | 24.9% |
| 6.20 (уровень 9, зелёная) | 11.9% |
| 10.00 (уровень 12, красная) | 6.9% |
| 50.00 (ограничение) | 1.1% |

Медианная точка краха — около **x1.78**. Примерно 1% раундов упирается в `max_multiplier`, где шар
лопается принудительно.

### Отдача и влияние параметров

Если игрок заранее решает забрать выигрыш на коэффициенте `m` (без бустера), ожидаемый возврат на
единицу ставки равен:

```
EV(m) = m * P(crash >= m) = (1 - instant_crash_probability) * m ^ (1 - alpha)
```

При `alpha = 1.15` это `0.97 * m^(-0.15)`: 93.8% при выходе на x1.25, 87.4% на x2, 76.3% на x5 — чем
жаднее стратегия, тем ниже отдача. Отсюда правила настройки:

- `alpha = 1.0` даёт постоянную отдачу `1 - instant_crash_probability` независимо от стратегии;
- `alpha > 1` наказывает долгие полёты (текущая настройка), `alpha < 1` наоборот делает их выгодными и опасно повышает отдачу;
- `instant_crash_probability` сдвигает отдачу линейно и вниз для всех стратегий;
- `max_multiplier` обрезает хвост распределения и незначительно снижает отдачу самых рискованных стратегий.

Бустер повышает отдачу вариантов ставки с множителем: при активации на уровне `L` выигрыш умножается
на `multiplier_tier_N_value`, при этом момент краха не меняется. Итоговый баланс экономики
настраивается совместно `alpha`, значениями бустеров и распределением `lootProbabilities`: чем выше
вероятность бустера на дальних уровнях, тем реже он успевает сработать.

## 2. Рост коэффициента

Коэффициент растёт геометрически по номеру тика:

```
base(t) = (1 + multiplier_growth_rate) ^ t,   t = 1, 2, 3, ... — номер серверного тика
такт тика = 1000 / fps миллисекунд
публикуемое значение = floor(значение / delta) * delta
```

При значениях по умолчанию (`multiplier_growth_rate = 0.012`, `fps = 20`) коэффициент удваивается
примерно за 2.9 секунды:

| Коэффициент | Время полёта |
| --- | --- |
| x1.25 | 0.9 с |
| x2.00 | 2.9 с |
| x6.20 | 7.6 с |
| x10.00 | 9.7 с |
| x50.00 | 16.4 с |

Клиент интерполирует значения между тиками по той же формуле и синхронизируется по каждому серверному
сообщению, поэтому анимация идёт в 60 fps, оставаясь честной.

## 3. Уровни

Уровень — это порог коэффициента из `levelMultipliers` соответствующей темы: 9 порогов у зелёной темы
и 12 у красной. Пересечение уровня начисляет `points_per_line` игровых очков и открывает кнопку
«Забрать» (после первого уровня). Пороги обязаны строго возрастать — это проверяет валидатор
конфигурации.

Отображаемый коэффициент = `base(t) × boosterFactor`, где `boosterFactor` равен значению бустера
после его активации и 1 до неё. Крах сравнивается с `base(t)`, поэтому бустер увеличивает выигрыш, но
не приближает и не отдаляет момент разрушения шара.

## 4. Позиция бустера

Для вариантов ставки с бустером x2 и выше уровень с бустером выбирается взвешенно:

```
P(уровень i) = lootProbabilities[i] / sum(lootProbabilities)
```

Значения нормируются автоматически, поэтому их не обязательно приводить к сумме 1. Для варианта без
бустера (`boosterTier = 1`) уровень не выбирается вовсе. Бустер срабатывает только если шар дошёл до
уровня раньше, чем игрок нажал «Забрать».

## 5. Начисление очков

| Событие | Параметр |
| --- | --- |
| Пересечение уровня | `points_per_line` |
| Успешный cashout | `points_cashout_bonus` |
| Активация бустера x2 / x3 / x4 | `points_x2_bonus` / `points_x3_bonus` / `points_x4_bonus` |

Очки за уровни и бустер начисляются в момент события, бонус за cashout — при фиксации выигрыша.
После cashout шар продолжает полёт, но новые очки не начисляются и бустер не активируется.

## 6. Расчёт выигрыша

```
выигрыш = round(ставка × зафиксированный коэффициент)
```

Ставка списывается при старте раунда, выигрыш зачисляется сразу в момент cashout. Если игрок не успел
нажать «Забрать», выигрыш равен нулю.

## 7. Честность и воспроизводимость

Перед полётом сервер формирует секрет `serverSeed` (32 случайных байта) и публикует
`commitHash = SHA-256(serverSeed:crashMultiplier:lootLine)`. После краха клиент получает `serverSeed`
и точную точку краха, поэтому может пересчитать хеш и убедиться, что результат не менялся во время
полёта. Хеш видно на игровом экране, раскрытый секрет — на экране результата.

Генератор детерминирован по seed: `Random` инициализируется первыми 8 байтами `SHA-256(seed)`.
Поэтому параметр `dev.fixedSeed` в конфигурации превращает раунды в полностью воспроизводимые, что
удобно для отладки и демонстрации: с одинаковым seed точка краха и позиция бустера повторяются.

Проверять влияние случайных параметров нужно серией запусков или расчётом по формулам выше, а не по
исходу одного раунда.
